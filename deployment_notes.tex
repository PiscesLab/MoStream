\section{Fresh Node Quickstart (run when CloudLab nodes are replaced)}

When nodes die and new ones are allocated, follow this checklist in order.
IPs will change --- update them in the scripts before running.

\subsection{Step 1 -- Update SSH aliases on local machine}
Edit \texttt{\textasciitilde/.ssh/config} with the new hostnames/IPs.

\subsection{Step 2 -- Clone repo and run setup scripts on each node}
\begin{lstlisting}
# On ALL nodes (apt051, apt041, apt063, apt055):
git clone git@github.com:do4am/MoStream.git ~/MoStream
cd ~/MoStream

# Then run the node-specific setup script:
# apt051:  bash cloudlab/setup_kafka.sh
# apt041:  bash cloudlab/setup_jobmanager.sh
# apt063:  bash cloudlab/setup_taskmanager.sh
# apt055:  bash cloudlab/setup_simulator.sh
\end{lstlisting}

\subsection{Step 3 -- Copy large data files (not in git)}
\begin{lstlisting}
# From local machine:
# Search space file (required by InferFunction on TaskManager):
scp MOS-search-simple.txt \
  jobmanager:~/MoStream/MoStream/MDStream/StreamML/search_space/
scp MOS-search-simple.txt \
  taskmanager:~/MoStream/MoStream/MDStream/StreamML/search_space/

# Simulator dataset:
ssh simulator "sudo mkdir -p /mnt/media/MDStream/WLGenerator/dataset && \
  sudo chmod 777 /mnt/media/MDStream/WLGenerator/dataset"
scp training-data-simple.txt \
  simulator:/mnt/media/MDStream/WLGenerator/dataset/
\end{lstlisting}

\subsection{Step 4 -- Update hardcoded IPs in scripts}
Edit the following with the new node IPs:
\begin{itemize}
  \item \texttt{cloudlab/submit\_job.sh}: \texttt{KAFKA\_HOST} and \texttt{TM\_IP}
  \item \texttt{cloudlab/setup\_jobmanager.sh}: \texttt{TM\_IP} default value
  \item Flink config on apt041: run \texttt{setup\_jobmanager.sh} which auto-detects JM IP
\end{itemize}

\subsection{Step 5 -- Start services (in order)}
\begin{lstlisting}
# 1. apt051: start Kafka
cd ~/MoStream && docker compose up -d
docker compose exec kafka /opt/kafka/bin/kafka-topics.sh --create \
  --topic Simulation --bootstrap-server localhost:9092 --partitions 1 --replication-factor 1
docker compose exec kafka /opt/kafka/bin/kafka-topics.sh --create \
  --topic Recommend --bootstrap-server localhost:9092 --partitions 1 --replication-factor 1

# 2. apt063: start TaskManager
~/flink/bin/taskmanager.sh start

# 3. apt041: start JobManager and submit job
~/flink/bin/jobmanager.sh start
bash ~/MoStream/cloudlab/submit_job.sh   # also auto-fixes DNS

# 4. apt055: run simulator
cd ~/MoStream/MoStream/WLGenerator-node1
KAFKA_BOOTSTRAP=<kafka-ip>:9092 python simulator.py --interval 1.0
\end{lstlisting}

\section{Node 0 -- apt051 (Kafka)}

\subsection{One-time fixes}

\textbf{Docker storage driver (overlayfs broken on this node):}
\begin{lstlisting}
# /etc/docker/daemon.json
{
  "data-root": "/opt/docker-data",
  "storage-driver": "vfs"
}
sudo systemctl restart docker
\end{lstlisting}

\textbf{Why:} The node's overlayfs has corrupted \texttt{\_\_pycache\_\_} directories that
cannot be deleted even after reboot. The \texttt{vfs} driver copies files instead of using
overlayfs, bypassing the corruption.

\subsection{Kafka image -- v2 change}

Confluent \texttt{cp-kafka:7.2.1} and \texttt{cp-zookeeper:7.2.1} crash on startup due to
\texttt{ModuleNotFoundError: No module named 'docker.types.daemon'}. This is a broken Python
dependency inside the Confluent image (\texttt{confluent-docker-utils} requires an old
\texttt{docker} library that removed that module in v7+). Affects all Confluent versions tested
(7.2.1, 7.3.3, 7.6.1).

\textbf{Fix:} Switch to \texttt{apache/kafka:3.7.0} (KRaft mode -- no Zookeeper needed):
\begin{lstlisting}
# docker-compose.yml
services:
  kafka:
    image: apache/kafka:3.7.0
    ports:
      - "9092:9092"
    environment:
      KAFKA_NODE_ID: 1
      KAFKA_PROCESS_ROLES: broker,controller
      KAFKA_LISTENERS: PLAINTEXT://:9092,CONTROLLER://:9093
      KAFKA_ADVERTISED_LISTENERS: PLAINTEXT://${KAFKA_HOST:-localhost}:9092
      KAFKA_CONTROLLER_LISTENER_NAMES: CONTROLLER
      KAFKA_LISTENER_SECURITY_PROTOCOL_MAP: CONTROLLER:PLAINTEXT,PLAINTEXT:PLAINTEXT
      KAFKA_CONTROLLER_QUORUM_VOTERS: 1@localhost:9093
      KAFKA_OFFSETS_TOPIC_REPLICATION_FACTOR: 1
      CLUSTER_ID: MkU3OEVBNTcwNTJENDM2Qk
\end{lstlisting}

\subsection{Start Kafka}
\begin{lstlisting}
cd ~/MoStream
KAFKA_HOST=KAFKA_HOST docker compose up -d
\end{lstlisting}

Verify:
\begin{lstlisting}
docker compose ps
\end{lstlisting}

\subsection{Create topics (after every Kafka restart)}

\textbf{Note (v2):} The \texttt{apache/kafka} image puts scripts at
\texttt{/opt/kafka/bin/}, not in \texttt{\$PATH}.
\begin{lstlisting}
docker compose exec kafka /opt/kafka/bin/kafka-topics.sh --create \
  --topic Simulation --bootstrap-server localhost:9092 \
  --replication-factor 1 --partitions 1

docker compose exec kafka /opt/kafka/bin/kafka-topics.sh --create \
  --topic Result --bootstrap-server localhost:9092 \
  --replication-factor 1 --partitions 1

# Verify
docker compose exec kafka /opt/kafka/bin/kafka-topics.sh \
  --list --bootstrap-server localhost:9092
\end{lstlisting}

\subsection{Monitor messages}
\begin{lstlisting}
# Stream live messages from a topic
docker compose exec kafka /opt/kafka/bin/kafka-console-consumer.sh \
  --bootstrap-server localhost:9092 \
  --topic Simulation --from-beginning

# Check message count (offset = number of messages)
docker compose exec kafka /opt/kafka/bin/kafka-get-offsets.sh \
  --bootstrap-server localhost:9092 --topic Simulation
\end{lstlisting}

\section{Node 1 -- apt041 (Flink JobManager)}

\subsection{One-time fixes}

\textbf{Fix DNS (not persistent across reboots):}
\begin{lstlisting}
sudo bash -c 'echo "nameserver 8.8.8.8" > /etc/resolv.conf'
\end{lstlisting}

\textbf{Fix Flink config -- use public IP instead of hostname:}

DNS for \texttt{apt041.apt.emulab.net} fails intermittently on this node. Use the public IP
in \texttt{\textasciitilde/flink/conf/config.yaml}:
\begin{lstlisting}
sed -i 's/apt041\.apt\.emulab\.net/KAFKA_HOST/g' ~/flink/conf/config.yaml
\end{lstlisting}

Verify:
\begin{lstlisting}
grep -E "rpc.address|address:" ~/flink/conf/config.yaml
# Expected: address: KAFKA_HOST  (all three occurrences)
\end{lstlisting}

\subsection{Package installs}
\begin{lstlisting}
source ~/miniconda3/etc/profile.d/conda.sh && conda activate mostream

# h5py 3.14 cannot read model.h5 (non-standard float type)
pip install h5py==3.1.0

# nfp must have GlobalUpdate + ConcatDense (saved with Keras 2.8.0)
pip install nfp==0.1.3
\end{lstlisting}

\subsection{Start JobManager}
\begin{lstlisting}
~/flink/bin/jobmanager.sh start
\end{lstlisting}

\textbf{Note (v2):} Do \textbf{not} use \texttt{start-cluster.sh} -- it tries to SSH into
the workers listed in \texttt{\textasciitilde/flink/conf/workers} to start remote TMs, but
SSH from apt041 to apt063 fails (key auth issue). Start each daemon separately instead.

Web UI: \texttt{http://apt041.apt.emulab.net:8081}

\subsection{Submit job}
\begin{lstlisting}
# Fix Windows line endings if script was committed from Windows
sed -i 's/\r//' ~/MoStream/cloudlab/submit_job.sh

bash ~/MoStream/cloudlab/submit_job.sh
\end{lstlisting}

\textbf{Note (v2):} \texttt{submit\_job.sh} uses \texttt{KAFKA\_HOST=KAFKA_HOST}
(public IP of apt051). The old \texttt{10.10.1.1} internal IP only exists on apt051's
Docker bridge -- it is not reachable from apt041.

\bigskip
\textbf{Known issues:}
\begin{itemize}
  \item Kafka topics wiped on \texttt{docker compose down} -- recreate after every restart.
  \item \texttt{systemd-resolved} broken on apt041 -- DNS fix (\texttt{nameserver 8.8.8.8})
        is not persistent across reboots; re-apply if node reboots.
  \item SSH from apt041 to apt063 by IP fails (host key / auth issue) -- start TM manually
        on apt063 instead of using \texttt{start-cluster.sh}.
  \item \texttt{submit\_job.sh} has Windows line endings (\texttt{\textbackslash r\textbackslash n})
        when committed from Windows; run \texttt{sed -i 's/\textbackslash r//' submit\_job.sh}
        on CloudLab before executing.
  \item \texttt{libtinfo.so.6} version warning from conda env -- harmless, does not affect execution.
  \item Model cold-start: NPMM returns \texttt{model\_not\_ready} until 16 messages accumulate.
  \item No Flink checkpointing -- trained weights lost if MDWorkflow crashes.
  \item \textbf{Python UDF crashes only occur under load:}
        When the simulator is NOT sending data, the Flink job stays up indefinitely with no
        errors. All crashes (Beam bundle timeout, gRPC channel reset) only appear once the
        simulator starts pushing messages. This confirms the failures are caused by Python UDF
        execution under load, not by cluster initialization or idle state.
  \item \textbf{Beam SDK harness crash (\textit{fixed}):} Job failed after 7--8 minutes with
        \texttt{RuntimeError: Channel closed prematurely}. Root cause: Beam's 1-second
        bundle timeout fired during CPU-intensive NPMM training.
        \textbf{Fix applied:} added to \texttt{\textasciitilde/flink/conf/config.yaml} on apt041:
        \begin{lstlisting}
python.fn-execution.bundle.time: 60000
python.fn-execution.bundle.size: 1
        \end{lstlisting}
        Result: job now runs past training and reaches the Kafka Sink stage.
  \item \textbf{Kafka Sink hardcoded to \texttt{localhost:9092} (\textit{fixed}):}
        \texttt{MDWorkflow.py} had a duplicate sink definition at the bottom of \texttt{workflow()}
        with \texttt{set\_bootstrap\_servers("localhost:9092")} overwriting the correct one above it.
        Since the Sink runs on the TaskManager (apt063), \texttt{localhost} pointed to apt063, not
        the Kafka broker. Symptom: \texttt{TimeoutException: Topic Result not present in metadata}.
        \textbf{Fix:} changed hardcoded \texttt{"localhost:9092"} to \texttt{kafka\_bootstrap} parameter.
  \item \textbf{gRPC IPv6 mismatch on apt063 (\textit{fixed}):} Job failed in 13 seconds with
        \texttt{grpc UNAVAILABLE: ipv6:[::1]:<port>: Connection reset by peer}.
        Java provision server bound to \texttt{127.0.0.1} (IPv4) but Python gRPC resolved
        \texttt{localhost} to \texttt{[::1]} (IPv6).
        \textbf{Fix:} add to \texttt{\textasciitilde/flink/conf/flink-env.sh} on apt063:
        \begin{lstlisting}
export JAVA_TOOL_OPTIONS="-Djava.net.preferIPv4Stack=true"
        \end{lstlisting}
  \item \textbf{Search space file missing (current blocker):} \texttt{InferFunction} looks for
        \texttt{StreamML/search\_space/MOS-search-simple.txt} in the distributed Python archive.
        File was absent from apt041, so it was never packaged and the TM returns placeholder
        results (\texttt{search\_space\_empty}). Fix:
        \begin{lstlisting}
# On local machine:
scp MOS-search-simple.txt \
  jobmanager:~/MoStream/MoStream/MDStream/StreamML/search_space/
# Hot-fix for running job (UUID from TM log):
scp MOS-search-simple.txt \
  taskmanager:/tmp/python-dist-<uuid>/python-files/StreamML/search_space/
        \end{lstlisting}
  \item \textbf{Stale TaskManagerRunner on apt041:} Multiple \texttt{start-cluster.sh} calls
        accumulate stale TM processes on the JM node. Kill with:
        \texttt{jps | grep TaskManagerRunner | awk '\{print \$1\}' | xargs kill -9}
        and clear \texttt{\textasciitilde/flink/conf/workers}.
\end{itemize}
