How MoStream Works

A real-time, closed-loop pipeline that discovers high-value molecules by letting a neural network steer expensive quantum-chemistry simulations toward the most promising candidates.

Simulators label molecules → Kafka → a Flink job trains a graph neural net, scores a search space, and ranks candidates → the best ones are streamed back to the simulators. The loop never stops.

The Big Picture

An endless active-learning loop

MoStream marries a slow, accurate physics simulator with a fast, approximate machine-learning model. The simulator produces ground-truth labels; the model learns from them and recommends where to look next — so the limited simulation budget is always spent on the molecules most likely to be valuable.

Inside the Engine

The Flink streaming state graph

This is the heart of MoStream: MDWorkflow.py wires a chain of operators into a directed dataflow. Data enters from Kafka, flows top-to-bottom, and every re-keying (⑂) reshuffles the stream across the cluster. Click any operator to inspect its role, state, keys, and exact input/output.

What makes it stateful

State travels with the stream

Unlike a batch ML job, nothing is stored in a database mid-flight. The model itself — its architecture and weights — is serialized to JSON and carried record-by-record through the pipeline, while Flink keyed state remembers the recent past on each parallel task.

🧠 Sliding train window

TrainFunction keeps a ValueState keyed by model_id: a FIFO list of the last 16 labeled molecules. Older records drop off as new ones arrive, so each model continuously fine-tunes on its most recent data.

📦 Weights-as-messages

After each model.fit(), all Keras weights are dumped to a JSON string and pushed downstream inside the stream tuple — alongside the model architecture JSON. Inference rebuilds the exact model from those two strings.

🗁 Cached search chunk

InferFunction holds a ValueState keyed by chunk_id: up to 500 candidate SMILES loaded once from the search space file, then reused for every inference on that chunk.

💾 Crash-proof checkpoints

Weights are also written to /tmp/mostream_weights_<subtask>.json so a recycled Beam Python worker resumes training instead of starting cold. Flink checkpoints every 30 s to flush the Kafka sink.

🎯 UCB acquisition

RankFunction scores each candidate with an Upper Confidence Bound (mean + std of predicted IP), sorts descending, and de-duplicates against everything already recommended — classic exploration/exploitation.

🔀 Re-keying shuffles

The stream is re-keyed three times — by model_id, then chunk_id, then windowed — letting Flink spread training and inference across all task slots in parallel.

Where it runs

6-node CloudLab deployment

🐍 Runtime

PyFlink jobs execute Python UDFs in Apache Beam workers pinned to conda env mostream (Python 3.9). TensorFlow + nfp + RDKit power the graph neural net.

🧬 The model

A Message-Passing Neural Network (neural fingerprint) that maps a molecular graph to a predicted ionization potential. Architecture is loaded once from model.h5.

📁 Shared data

Model file and search space live on /mnt/media (not NFS) to survive CloudLab filesystem resets. Training data seeds each simulator.
